# 垃圾分类语料标注与候选审核指南

标注的目标是描述原句中的实体和关系，不能把目录中已知的正确类别替代原句的实际含义。原句错误时仍应保留原文，并在事实审核阶段拒绝入库。

## 实体边界

使用 Python 字符下标，左闭右开 `[start,end)`。`text[start:end]` 必须等于实体文本。不要把标点、动词、限定语或垃圾桶名称并入物品实体。当前实体不允许重叠。

- `ITEM`：垃圾物品或材料，例如“香蕉皮”“废纸张”。
- `CATEGORY`：分类名称，例如“湿垃圾”“可回收物”。
- `METHOD`：原文连续出现的投放操作，例如“保持清洁干燥”。

BIO 标签为 O、B-ITEM、I-ITEM、B-CATEGORY、I-CATEGORY、B-METHOD、I-METHOD。I 标签只能接在同类 B/I 标签之后；训练和解码都约束非法转移。

“香蕉皮属于湿垃圾。”中，“香蕉皮”的跨度是 `[0,3)`，“湿垃圾”的跨度是 `[5,8)`。训练文件每行格式如下：

```json
{"text":"香蕉皮属于湿垃圾。","group":"香蕉皮","entities":[{"start":0,"end":3,"text":"香蕉皮","type":"ITEM"},{"start":5,"end":8,"text":"湿垃圾","type":"CATEGORY"}],"head":0,"tail":1,"relation":"BELONGS_TO","provenance":"manual_annotation"}
```

## 关系方向

`head` 和 `tail` 是 entities 数组下标，不是字符位置。BELONGS_TO 表示 ITEM → CATEGORY；DISPOSE_WITH 表示 ITEM → METHOD；NO_RELATION 表示该有向实体对没有可确认的肯定关系。一个句子可包含多个实体，标注文件可为不同有向实体对生成多条记录，但训练/验证/测试不能把同一句子拆到不同分区。

疑问、假设、转述的错误结论和明确否定应标为 NO_RELATION。条件句如果确实给出了有条件的类别，可在关系评测中标为正例，但事实入库必须保留条件。“干净的纸箱可回收”不能泛化为“所有纸箱可回收”。

## 人工审核顺序

1. 打开来源，核对候选证据确实存在，排除标题、导航、参考文献和截断片段。
2. 确认来源适用地区和发布时间。历史百科描述不能覆盖当前官方投放指引。
3. 检查实体边界、关系方向、否定和疑问、条件与例外。
4. 对照原文和当前目录，确认没有把大件垃圾、建筑垃圾、医疗废物等误塞入普通家庭四分类。
5. 逐条填写候选 id、approved 布尔值和实际审核人。错误候选保持未批准；有争议的条目先暂缓。
6. 合并后重新构图、复查变化，再导入 Neo4j。不能为了提高模型分数而修改测试标签。

## 建议的正式实验流程

由两人独立标注自然网页语料，记录分歧并仲裁；按来源网页或物品组隔离数据，近重复句聚类后整体分配。只用训练集拟合字表、模型和阈值；验证集用于调参，最终盲测集只报告一次。模板数据可用于初始化流程，但不能替代代表真实应用分布的评测集。

本项目中的改写挑战集已经用于诊断模型缺陷，因此归类为开发评估；网页小样本为单人标注，结果只说明这些具体句子的表现。
